# Lessons 5.15–5.18 (ring20 inception practice v0.3)

> Addendum, not a rewrite: our copy of the full practice (`T-2222-inception-protocol.md`) is v0.2 with lessons
> 5.1–5.14. These four lessons are the whole of v0.3's change ("Lessons 5.15–5.18 from the T-2250 orchestration
> inception"). Text below is ring20's, extracted from the rendered page named above; replace this file with the
> canonical v0.3 markdown when ring20 sends it.

5.15 Restate every id in one sentence when you ask about it (operator rule, 2026-10-06). Numbering everything
(3.2) makes ids common: open questions (IW-2), sections (§5E.2), gaps, tasks. An agent asked "IW-2?", and the
operator had to scroll back to find what it meant. Rule: whenever a message asks the operator to decide or know
something by id, put a one-sentence plain-language restatement next to it. Example: "IW-2 (whether the orchestrator
is armed per run by you, or always on with the halt file as the brake): …". It applies to chat, Watchtower
criteria, runme and approval hand-offs.

5.16 Cap review rounds per step at 2–3 (operator rule, 2026-10-06). Round after round keeps surfacing new
findings and never converges (step 2: 8 rounds, lesson 5.6; arc-008 step 5: 5+). After the cap, every remaining
finding is dispositioned or escalated, never reviewed again:

- accepted, with a change request;
- rejected, with a reason;
- deferred, with a risk acceptance.

Points raised in the final round go into the build spec as acceptance criteria, not into another review round.
Filed to AEF as a review-protocol pickup (proposed REVIEW_MAX_ROUNDS, default 3).

5.17 Do not invite a decision before it is decidable. In T-2250 the agent set the Recommendation to GO while four
open questions were still undisposed. Watchtower /approvals showed a GO button, the operator pressed it, and
fw inception decide refused it with the disposition gate. Two rules:

- Before pointing the operator at a decision, check readiness yourself: every IW-N disposed, Recommendation current
  after any scope change. While the inception is still being shaped, keep the Recommendation at DEFER with "shaping
  in progress".
- /approvals should apply the same readiness check as decide (filed to AEF; ring20 gap G-227).

5.18 Review routes: internal runs on the ladder, paid needs a go (operator rule, 2026-10-06). The three-vendor
panel (claude-code, codex, opencode on subscriptions) is internal and is dispatched by the risk ladder without
asking. Only paid routes need the operator's authorization each time.
Data leaving the estate is decided per route: each route has an id and approved data and risk classes, held in a
route ledger (T-2250 concept §5F). Note also: rung 5 stops at the first non-green seat. For a concept review that
needs every vendor's view, run the seats as parallel advisory consults instead.
