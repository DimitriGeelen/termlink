**Defects**

1. **MAJOR** — termlink-sidecar/src/consumers.rs:`verdict` — `is_me` accepts *any* entry with `agent == me_agent && instance == ACK_INSTANCE("-")` regardless of strength, so a claimed reader that spoofs the ack sentinel is classified as the sidecar itself and never flagged. — Repro: while fx-a's sidecar runs, call `channel.subscribe {topic: "inbox:H/fx-a", reader: {agent: "fx-a", instance: "-"}}` (unsigned, no sig); the hub records `(fx-a, "-", claimed)`, the sidecar's next check yields `others = []` and status `one (proven)` — the second consumer is invisible and no attention entry fires (pre-bind detection bypass; post-bind the hub still refuses it). — Fix: treat `instance == "-"` as me only when `strength == "proven"` (or capture `key_fp` and require it to equal the sidecar's own fingerprint).

2. **MAJOR** — termlink-hub/src/channel.rs:`consumer_gate` + inbox_consumers.rs:`record` — the gate records consumers *before* any topic-existence check and eviction admin rows are not rate-capped (only `inbox-bound-refused` is, 10/min), so any remote Observe caller grows `rpc-admin.jsonl` without bound and forces a full-table rewrite per RPC. — Repro: 4096 subscribes on distinct nonexistent `inbox:*` names fills MAX_TOPICS; each further subscribe on a fresh topic/topic-name evicts and logs `inbox-consumer-topic-evicted` and re-serializes the whole (up to ~4096×16 ≈ multi-MB) `inbox-consumers.json`; likewise cycling 17 agent names on one topic logs `inbox-consumer-evicted` per call — unbounded log growth and O(table) disk write per unauthenticated read RPC. — Fix: require the topic to exist on the bus before recording; rate-cap (or drop) eviction rows as T-3703 does; debounce persistence.

3. **MINOR** — termlink-sidecar/src/liveness.rs:`read` — the fallback to `channel.subscribe` fires on *any* `channel.first_at` error, not just `-32601`, and sends no `reader`. — Repro: on a T-3700 hub, one transient `first_at` error (-32603) makes liveness read the main's inbox content-free-read-less path as `(unnamed)` → the main's sidecar next tick reports "inbox consumed by two identities … (unnamed)" (false flag), and after a bind the fallback is refused → `Read::Unreadable`. — Fix: fall back only on `METHOD_NOT_FOUND`; treat other errors as Unreadable (or sign the fallback read naming the checker).

4. **MINOR** — termlink-hub/src/inbox_consumers.rs:`record` — a name-only claimant sending `{agent: me, instance: my-instance}` unsigned merges into the existing entry and overwrites `strength/key_fp/why` to claimed("unsigned"). — Repro: `channel.subscribe` with `reader {agent:"fx-a", instance:"inst-a"}`, no sig, while the real sidecar runs → its proven entry flips to `claimed`, status becomes `one (claimed: unsigned)`, no second-identity flag; coexistence is hidden (partly inherent to ruling E, but the table could refuse proven→claimed downgrades). — Fix: never let a `claimed` reader downgrade an existing `proven` entry (keep max strength, or key entries by strength too).

5. **MINOR** — inbox_consumers.rs:`load_state`/`record` — `load_error` is never cleared: after an unparseable file, saves succeed and repair the file, but `consumers()` keeps erroring until process restart. — Repro: corrupt `inbox-consumers.json`, restart hub, do one read (save succeeds, file rewritten), call `inbox.consumers` → still `consumer list unreadable` forever. — Fix: clear `load_error` on the first successful `save_consumers`.

6. **MINOR** — inbox_consumers.rs:`assess_ack` vs design §2.3 — an ack with no matching card is listed as `key:<fp[8..24]>` claimed, not the payload's claimed `from_agent`/`(unnamed)` as the design states. — Repro: post a validly signed receipt with an unknown key and `from_agent: "fx-z"` → entry agent is `key:…`, so operators grepping for `fx-z` miss it. — Fix: fall back to the post's `from_agent` (or `(unnamed)`) when no card matches.

7. **MINOR** — design §4.1 vs diff — the design says pull.rs, liveness.rs **and deliver.rs** carry signed readers, but the diff contains no deliver.rs change; if that path subscribes/claims an inbox it would be recorded unnamed (self-flagged each tick, refused after a bind).
