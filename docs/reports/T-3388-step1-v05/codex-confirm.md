## 1. Fidelity and completeness

**1a. Some [R] clauses exceed the rulings.** R-74.a(1) makes joining depend on hub availability; CR-15 and the OQ-12 decision require signed, countersigned membership events but do not rule that outage restriction. R-53.a extends access to all four reachability fields to the cockpit; D7 grants those fields to the operator and own project, while OQ-16 explicitly includes the cockpit only for the busy bit. Mark these additional choices [P] or, where accepted supporting detail warrants it, [R~]; do not present them as explicit rulings. (§6.1.h; threat model §21 CR-11/CR-15; T-3351 Decisions OQ-12, D7, OQ-16.)
**1b. Acceptance text acquires unsupported authority.** R-65.e requires rejection of a DEAD statement whose sequence is *equal* to the last seen; CR-12 requires signed, sequenced DEAD statements, not this strict-increase rule. R-51.e labels the crash-recovery mechanism [R], although R-51.a and §14.5.3 label its details [R~]. The blanket explanation in §6.1.i does not resolve these explicit local tags. (CR-12, CR-17; D4/D5.)
**1c. CR-21 is narrowed against the controlling decision.** R-79.a(2) prohibits vendor channels and sub-agents “for governed work.” The full RR-13 decision says they “are not used and never built on,” without that qualification. R-79.a(1)’s universal TermLink requirement consequently conflicts with the apparent exception in (2). Remove the qualification; this needs no new ruling. (§14.4 source precedence; T-3351 Decisions RR-13.)
**1d. CR-20 loses part of the forwarding notice.** R-67.a1(4) requires telling the sender the current main and generation, but omits the decision’s explicit “delivered via Y” information. Restore identification of the forwarding copy so the sender can distinguish forwarded delivery from direct delivery. (T-3351 Decisions RR-8, item 4; CR-20.)
**1e. All 20 accepted CRs have substantive coverage, but the touched-requirement mapping is incomplete.** CR-12 explicitly names R-60; its v0.5 amendment covers CR-8 only and never adds or references signed/sequenced DEAD. CR-18 names R-60 and R-61, but §14.1 maps only R-72/R-64, leaving those requirements without explicit approval-route integration. Add the relevant cross-references and mapping entries. CR-16’s rejected one-year retention class was not introduced. (Threat model §21 CR-12/CR-18; requirements §14.1–14.2.)
## 2. Internal contradictions
**2a. Outage behavior still has conflicting active specifications.** R-44.e requires UNKNOWN whenever the destination hub is unreachable, contradicting R-44.a/R-45.a when circuit receipts remain available. D-1/D-2 and §§3.1.1.c, 3.2.1.c/i retain unconditional hub-first recording or hub-only reply retrieval; §3.3.1.g and the §5 glossary likewise define states exclusively from the hub record. Add the CR-1 exception throughout these current descriptions. (CR-1; R-2, R-26, R-44, R-45.)
**2b. Timeout-based redelivery contradicts the evidence-complete rule.** R-24.e makes a message eligible again after the evidence window expires. D-3 and §3.3.1.d likewise return ATTEMPTED to QUEUED merely because evidence is absent. R-47.a/R-51.a now require proof of absence at the adapter’s evidence-complete point, or an operator wait after an uncertain crash. A timeout alone cannot authorize that retry. (CR-17; D4; threat model §21.2.1.)
**2c. Membership fencing is expressed incorrectly.** R-74.a(5) rejects an old participant only when its authority-ending epoch is *below the turn’s epoch*. An old copy sending with its old epoch does not satisfy that condition, yet R-74.e explicitly requires rejection of that case. State fencing against the receiver’s authoritative membership state, retaining the accepted outage-expiry limitation in R-74.g. (CR-15; OQ-12/OQ-17; PR-30.)
**2d. The current diagrams/glossary retain superseded doorbell semantics.** §3.2.1.e still promises nothing is typed into a busy prompt; D-1/D-2 describe typing based simply on a free prompt, without the immediate re-check and veto. The §5 Doorbell entry still labels “no peer content” [P], although R-23.a promotes it to [R]. Update these current summaries to CR-5. Explicitly preserved historical quotations need not be deleted. (OQ-16; R-19.r, R-23.a, R-81.)
## 3. Non-CR rulings and step 3
**3a. OQ-1: omission would mislead.** §2.3 and D-1 stop at ADV-10, despite R-72.f already relying on ADV-11/12. Add the confirmed ADV-11–14 scope or an explicit authoritative incorporation. Step 3 must defend against all fourteen. (OQ-1; threat model §4.3.)
**3b. OQ-2: omission would mislead.** R-72.g/R-78.g mention account separation as a dependency but omit the committed target and its delivery obligations: isolated accounts, narrow privileged helper, human-approved/logged Tier 0 creation, and step-3 phasing. Also preserve host root as a permanent residual, not something account separation eliminates. (OQ-2; §13.5.)
**3c. OQ-5: omission would mislead.** R-15.d/e tests a sidecar restart, not the ruled host-crash durability floor. Incorporate F-1/F-2 survival, flush before STORED, visible F-3–F-5 detection, and F-6/F-7 refusal or detection. (§8 GP-13; OQ-5; threat model §12.2.)
**3d. OQ-15 is already substantially folded.** R-51.a and §14.2 explicitly prohibit retention beyond the stage-memory window and distinguish telemetry digests. The defect is §14.5.6/fold-report §4 saying otherwise, plus omission of the ruled revisit trigger if measurements show re-sends older than 14 days. (OQ-15.)
