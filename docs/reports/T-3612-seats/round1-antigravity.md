# Independent Review: What TermLink Is and What It Is Becoming

## 1. What TermLink IS Today

In code and daily use, TermLink is a 9-crate, 196,899-LOC Rust workspace (`Cargo.toml:3-13`) wrapped in a massive shell-and-governance operational harness (`scripts/`: 266 files, 57,791 LOC; `tests/`: 229 files, 33,464 LOC; `.context/cron/`: 49 crontabs; `runme.sh`: 2,048 lines; `.claude/commands/`: 37 skills) that serves as the IPC, terminal-control, and worker-dispatch nervous system for a multi-host AI agent homelab (`ring20`). By code volume, 61% of the Rust workspace sits in two surface monoliths—`crates/termlink-cli` (72,857 LOC; 57 top-level subcommands in `src/cli.rs:16-280`, dominated by `src/commands/channel.rs` at 21,275 LOC and `src/commands/remote.rs` at 12,285 LOC) and `crates/termlink-mcp` (47,791 LOC; 273 `#[tool]` definitions in `src/tools.rs`). Beneath those surfaces sit four real runtime subsystems: (1) POSIX PTY/session lifecycle and command execution over Unix sockets (`crates/termlink-session`, 24,558 LOC); (2) a TCP/Unix JSON-RPC and WebSocket hub (`crates/termlink-hub`, 27,481 LOC) backed by content-addressed artifacts, append-only topic logs, and SQLite metadata (`crates/termlink-bus`, 11,518 LOC); (3) a local mailbox-to-prompt delivery daemon with hash-chained stage records and Claude Code hook adapters (`crates/termlink-sidecar`, 8,271 LOC, built in `T-3402`..`T-3442`); and (4) a Compare-And-Swap (CAS) fenced dispatched-worker state machine (`crates/termlink-bus/src/worker_contract.rs`, `crates/termlink-hub/src/dispatch_contract.rs`, built in `T-3501`..`T-3504`). Rather than a lightweight cross-terminal utility, TermLink today is a bespoke, single-operator fleet runtime and self-surveillance harness tightly coupled to Claude Code and the Agentic Engineering Framework (AEF).

## 2. What It Is FOR

* **Who uses it:** One human operator (`DimitriGeelen`) and a co-operating fleet of ~15–20 AI agents (primarily Claude Code, alongside OpenCode, Codex, Antigravity, and local Ollama workers) across `ring20` hosts (`.107`, `.121`, `.122`, `.132`, `.141`; `docs/architecture/parallel-execution-substrate.md:22-24`, `runme.sh:393`, `T-3612:79`).
* **Jobs it performs:**
  1. **Cross-agent durable messaging and wake-up:** Posting and subscribing to `dm:`, `inbox:`, and broadcast topics (`framework:pickup`), pushing sub-second WebSocket wake signals (`arc-004`, `crates/termlink-session/src/ws_consumer.rs`), and handing messages into idle agent prompts via hooks or PTY injection (`crates/termlink-sidecar/src/adapter/claude.rs`, `scripts/notify-injector.sh`).
  2. **Parallel worker dispatch and multi-vendor panels:** Spawning isolated headless or `tmux` agent workers (`scripts/tl-dispatch.sh`, `crates/termlink-cli/src/commands/dispatch.rs`), used live for multi-seat reviews (`T-3304`, `T-3612`) and autonomous `[Review, Audit, procAsFit]` loops (`T-3609`).
  3. **Remote terminal observation and actuation:** Inspecting PTY scrollback, classifying prompt quiescence (`scripts/lib/pty-state.sh`, `T-3079`), and running commands across LAN hosts (`remote exec`, `T-3323`).
  4. **Fleet self-surveillance and one-command operator execution:** Running 49 cron canaries and executing batched root/governance actions idempotently via `/opt/termlink/runme.sh` (`CLAUDE.md:128`, `T-3272`).
* **Stated intent vs. evidence:** `README.md:18-29` presents four equal verbs (`discover`, `channel post/subscribe`, `channel claim`, `spawn/exec/pty`). The 5-run Value Review (`docs/reports/VALUE-REVIEW-repo-2026-09-19-consolidated.md`, findings `C-36`, `C-30`..`C-34`) proved that over 34.2 days, `channel.post`/`create` exceeded 106,000 calls, whereas Verb 3 (`channel claim`) had **zero production callers** (108 calls = 0.012%, all demos/provers) and `kv.*`/`event.*` had zero hub-observed calls. I believe the telemetry: `claim` was built ahead of consumer adoption.
* **What would be lost if it disappeared:** The `ring20` fleet would lose cross-host and cross-project agent coordination, parallel multi-vendor worker dispatch, and automated prompt delivery; the human operator would be forced back into acting as a manual copy-paste courier between isolated terminal sessions (`.context/project/objectives.yaml:75-79`).

## 3. What It Is BECOMING (2026-08-27 .. 2026-10-27)

Across 2,087 commits and 754 tasks created in the last two months, six concrete shifts define TermLink's trajectory:

1. **From best-effort PTY wake to a cryptographic, transcript-evidenced Sidecar Delivery Rail (`2026-09-21 .. 2026-10-18`, `arc-011`, `T-3049`..`T-3464`):** After discovering on `2026-09-21` that the `arc-003` notify rail had been dark for 82 days (`T-3049`, `runme.sh:221`) and that `evidence=wake-consumer` falsely reported unread messages as read (`arc-011.yaml:410-416,698`), the project rebuilt terminal idle detection (`T-3069`/`T-3079`, `2026-09-22`), ran an 8-step formal specification and threat-modeling chain (`T-3344`..`T-3352`, `2026-10-04..10-11`), and built `crates/termlink-sidecar` (`T-3402`..`T-3442`, folded into `termlink sidecar` under `T-3365`). 2. **From stateless message router to Authoritative Coordination and Dispatch Record (`2026-10-01 .. 2026-10-27`, `arc-012`, `T-3304`, `T-3484`):** On `2026-10-01` (`T-3304` IW-1 ruling B), the operator ruled the hub is the queryable source of truth within a bounded retention window (14-day default, retention-gap notices, `forever` topics requiring a named owner, `T-3310`). 3. **From strict-star topology to hub-brokered peer circuits and directory cards (`2026-10-04 .. 2026-10-11`, `T-3344` OD-1/OD-11, `T-3351`):** The operator ruled in `docs/reports/T-3344-step1-rulings-summary.md:93-107` that hubs will exchange signed project directory cards (OD-11) and mint short-lived credentials for direct sidecar-to-sidecar circuits with hub fallback (OD-1, phased at PH-5 in `docs/design/interactive-agent-communication-03-floor-and-phasing.md:99-101`).
4. **From coarse host-level trust to per-agent cryptographic attribution and OS user isolation (`2026-10-01 .. 2026-10-22`, `T-3302`, `T-3351`, `T-3493`, `T-3548`..`T-3553`):** Following the `2026-10-11` root inventory showing all 115 sessions running as `uid 0` (`T-3395`), a `2026-10-12` agent `tmux` command that stripped execute permissions from `/` (`T-3425`), and a `2026-10-22` cross-project `tmux` environment leak (`SEV-1 T-3549`, `T-3548`), TermLink is moving to per-agent ed25519 keys (`T-3302`, `T-3438`), signed PTY inject with allowlists (`T-3493`/`T-3534`), supervisor tokens (`T-3501`), and per-project Unix accounts (`T-3553`, Track A).
5. **From manual operator commands to a locked, self-verifying root actuator (`2026-09-22 .. 2026-10-27`, `T-3052`, `T-3272`..`T-3299`, `T-3574`, `T-3592`):** `runme.sh` became the sole operator actuation interface (`CLAUDE.md:128`), handling binary builds (`local-fast`, `T-3292`), systemd/cron installs, hub restarts (`T-3290`), and batch human-ownership handbacks (`T-3592`).
6. **From Claude-only scripts to a multi-harness adapter contract (`2026-10-03 .. 2026-10-26`, `T-3344` OD-7, `T-3372`):** Abstracting hook/readiness logic behind `crates/termlink-sidecar/src/adapter/` for OpenCode (`055`) parity.

## 4. Proposed Purpose Statement

**TermLink is the verifiable coordination, messaging, and session-control substrate that lets a multi-host fleet of AI agents and their human operator discover live peers, deliver durable and transcript-proven messages, execute fenced worker dispatches, and supervise terminal sessions.**

It pairs a central hub—acting as the bounded, authoritative record for message stages, presence, and `wc/0.3` worker state transitions—with local per-agent sidecars and POSIX PTY endpoints that safely bridge network traffic into running agent prompts. Every message hand-over, lifecycle transition, and terminal injection is cryptographically attributable to a specific agent, supervisor, or operator identity and fails loudly rather than silently dropping work. TermLink supplies the transport, durability, and execution primitives; higher-level workflow planning and task decomposition remain in the consuming framework.

## 5. Proposed Objectives

1. **Truthful Reachability & Liveness (revises `O-1`):** Queries for available peers return only live sessions with an active, verified delivery path (hook sidecar or PTY waker) and fresh surfacing progress (`CAND-6`), never stale ghosts or deaf sessions.
   * *Measure:* Daily two-agent delivery canary (`T-3361`) and `termlink sidecar status` reachability cards show 100% agreement between advertised `LIVE/CLEAR` state and actual message hand-over within 2 ticks (60s).
2. **End-to-End Evidenced Message Delivery (revises `O-2`):** No accepted message is silently lost or typed into a busy prompt; every message progresses through signed, hub-recorded stages (`SENT -> RECEIVED -> STORED -> HANDED_OVER -> REPLIED | ACKNOWLEDGED_NO_ACTION`) or surfaces as `STUCK`/`DEAD` within its R-44.e deadline (`T-3428`), and readers whose cursor was swept receive an explicit retention-gap notice (`arc-012`).
   * *Measure:* Zero unconfirmed-delivery or dead-letter silent drops across 14-day soak (`H-14`); 100% of `HANDED_OVER` receipts carry a verified transcript nonce (`SI-17`); hub `rpc-audit.jsonl` records 0 `channel.post`/`create` calls >5s under <90% disk load (`T-3488`).
3. **Fenced, Single-Record Worker Dispatch (revises `O-3`):** Every dispatched work attempt is tracked once in the shared `wc/0.3` hub record (`wc_dispatches`/`wc_attempts`), protected against split-brain writes by CAS nonces and supervisor tokens, automatically swept to `lost`/`unknown` on session death or timeout, and executed in an isolated workspace without environment leakage.
   * *Measure:* 100% pass rate on the shared `tests/contract-vectors/` suite (`CC-01`..`CC-16`, `T-3517`/`T-3602`) across TermLink, AEF, and `ring20`; zero cross-project variable leaks in `env-leak-canary` (`T-3551`).
4. **Leak-Free, Attributable Terminal Session Control (revises `O-4`):** Agents and operators can spawn, observe, and execute commands in local or remote PTYs with zero orphaned sockets/processes and without unauthenticated peers injecting keystrokes.
   * *Measure:* `scripts/session-selftest.sh` passes daily; zombie-session count stays below threshold after daily reap (`T-3491`); 100% of `command.inject` calls on protected sessions require a verified sender key on the session's allowlist (`T-3493`/`T-3534`).
5. **Least-Privilege Identity & Host Isolation (revises `O-7`):** Every bus post, sidecar stage, worker transition, and operator resolution is cryptographically bound to a distinct agent, supervisor, or operator key, and co-resident projects cannot read each other's keys or sidecar sockets.
   * *Measure:* Zero unsigned or host-shared-key posts accepted in production mode (`SI-3`, `T-3467`); sidecar status strength flags (`A` per-agent OS accounts, `K` operator key, `03-floor-and-phasing.md:67`) progress from absent to verified across all `ring20` hosts (`T-3553`).
6. **Bounded Surface & Zero-Toil Operator Ergonomics (revises `O-5`, `O-6`):** Shipped code matches live fleet binaries, operator actions require at most one self-verifying command (`/opt/termlink/runme.sh`), and CLI/MCP/context surfaces stay within strict token and complexity budgets.
   * *Measure:* Fleet binary/capability drift canaries report 0 unacknowledged mismatches; per-tool/per-verb invocation telemetry (`C-45`) is live; MCP description payload stays <15k tokens (`C-05`) and `CLAUDE.md` preload stays <20k tokens (`C-04`) after pruning zero-caller deprecated/analytics tools (`C-01`, `C-02`).

The existing drivers (`D1`–`D4`, `F-RECALL`, `F-ORCH`) were inherited from AEF and poorly fit a Rust systems/coordination substrate (`T-3612:49-51`):

## 7. Non-Goals (and Drift to Stop)

1. **Not a social chat or engagement analytics platform (STOP DRIFTING):** `docs/CHARTER.md:43-45` states this, yet `crates/termlink-cli/src/commands/channel.rs` and `crates/termlink-mcp/src/tools.rs` still compile and advertise emoji reactions, stars, pins, polls/voting (`PollStart`, `Vote`), typing indicators (`Typing`, `Typers`), and 28 analytics/leaderboard tools (`EmojiStats`, `QuoteStats`, `agent_rankings`), plus 40–46 deprecated tools (`C-01`, `C-02`). TermLink must execute the `T-2548` / `p4-surface-reduction` deletions immediately.
2. **Not a general-purpose host monitoring or AEF governance script repository (STOP DRIFTING):** With 49 crontabs and 266 scripts—including root-filesystem permission canaries (`T-3425`), AEF hook-telemetry workarounds (`C-20`), and 105 MB of handovers/audits vs. ~6 MB of Rust code (`C-25`)—the repo is drifting into an ad-hoc host-ops monorepo. Governance policy and framework self-checks belong upstream in AEF (`G-062`); host-OS administration belongs in `ring20`.
3. **Not an automatic cross-hub message-relay mesh:** Keep Charter Non-goal #1 (`docs/CHARTER.md:34-39`, guarded by `crates/termlink-hub/tests/no_federation_tripwire.rs`), but amend its wording to reflect `T-3344` OD-1/OD-11: hubs never auto-relay topic messages, though they may exchange signed project directory cards and mint credentials for explicit sidecar circuits.
4. **Not a long-term archival database:** Keep Charter Non-goal #2 as refined by `T-3304`: the hub is the authoritative coordination and `wc/0.3` dispatch record *within a bounded retention window* (default 14d; 30/180d for dispatch tombstones), not an unbounded forever-log.
5. **Not a high-level workflow planner or task decomposer:** Keep Charter Non-goal #4, sharpened for `wc/0.3` and `arc-011`: TermLink owns transport, delivery state machines (`termlink-sidecar`), and fenced execution records (`worker_contract.rs`), but *what tasks to create, how to decompose write-sets, and when to promote work* belong to AEF. Remove dead `orchestrator.route` hub scaffolding (`crates/termlink-hub/src/router.rs:78,1186`, `C-27`).
6. **Not a hostile multi-operator cloud service, Carry-on Root Co-Tenancy Must End:** Refine Charter Non-goal #5 (`objectives.yaml:109`): TermLink serves a single operator's fleet, not untrusted public tenants, *but* it must stop running all co-resident project agents as shared `uid 0` (`root`) in a shared `tmux` server (`T-3395`, `T-3548`, `T-3553`).
