(a) The record is an append-only ledger with a single writer (the supervisor, under a lease), keyed by commission id = the AEF dispatch_id of attempt 1. Attempts are numbered, so the fencing token is (commission, attempt) plus a random per-attempt nonce in the prompt that the hand-back must echo.
(b) 'done' is never a worker-written event. The supervisor reads the hand-back only from a root-owned stdout file, only after the unit is inactive, and only the last fenced block with the right nonce. The capability is the channel, not a token the worker holds. Older-attempt events are logged as fence_reject.
(c) 'lost' is written only after the worker is confirmed gone (unit inactive). Never on a missed heartbeat, and a live unit is never marked lost. If the hub writes lost, I'd make it require the same 'session confirmed gone' evidence.
(d) The result is the output hash (commit sha or hand-back sha256), and the review verdict must name that hash.
(e) Recovery rules per last state, especially 'launching' with an uncertain launch, are the part people underestimate (§7).
