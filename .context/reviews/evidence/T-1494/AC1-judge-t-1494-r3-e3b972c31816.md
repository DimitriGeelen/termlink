# T-1494 Human AC#1 — on-thread --watch steady (no flicker) and readable

Reviewer: independent (rung-3-termlink-single-reviewer). Revision 49026cef6.

## What I ran
From /opt/termlink, under a real pty (`script -f --log-timing`) so that the output and timings match a terminal session:

    timeout -s INT 13 script -q -f -c "target/release/termlink agent on-thread T-1438 --watch --watch-interval 5 --window-secs 86400 --n 5" typescript --log-timing=timing

It produced 3 ticks (more than the 2 the AC asks for). SIGINT (Ctrl-C equivalent) then ended the process cleanly, and script reported COMMAND_EXIT_CODE=0.

## Findings
- **Full redraw per tick:** every frame begins with `ESC[2J ESC[H` (clear the screen, cursor home), then the header and the full body. There is no appending or scrolling between frames. Code: crates/termlink-cli/src/commands/agent.rs, cmd_agent_on_thread watch loop (`print!("\x1b[2J\x1b[H")`).
- **Flicker measurement (from the timing log):** each tick writes the clear plus header (100 B) first. The post body follows **16 ms / 18 ms / 25 ms** later. Ticks are 5.001 s apart. A blank window of about one display frame cannot be seen as flicker at a 5 s cadence. The display is steady.
- **Header shows the current ts:** `# agent on-thread T-1438 --watch | interval=5s | window=86400s | n=5 | 2026-10-27T14:59:49Z`, then `...14:59:54Z`, then `...14:59:59Z`. The timestamp moves forward exactly 5 s per tick.
- **Posts visible:** each frame lists 5 posts (`[3h ago] @2750 peer=... msg_type=chat project=...` followed by the indented body) and ends with the footer `5 post(s) shown`. A long ALERT body is cut off with `…`, so a single post cannot flood the screen. Posts are separated by blank lines and relative ages are shown. The view is readable.

## Note (not blocking)
The screen is cleared *before* the hub fetch, so the blank window equals the fetch latency. Against the local hub this is about 20 ms. Against a slow or remote `--hub` it could become a visible blink. A possible hardening step: fetch first, then clear and draw in one buffered write. This is not required for this AC.

Verdict: green.
