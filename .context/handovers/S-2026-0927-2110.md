## Gotchas / Warnings for Next Session

**1. The Tier-1 write gate changed under you. Twice.** `has_bash_write_pattern()` in
vendored `safe-commands.sh` now: (a) treats `2> file` and `&> file` as WRITES — they were
bypasses; (b) no longer treats a filename containing `-i` as `sed -i`; (c) exempts

suddenly gated, check `tests/safe-commands-write-pattern-fixtures.sh` (44 assertions)
before assuming the gate is broken.

**2. `fw bvp confirm` no longer refuses you, and neither do the other four verbs.** You can
score, set weights, add/remove drivers and enable auto-promote without `--i-am-human`. But
**a human-set score is STICKY** — `bvp_scores_source: human` makes the agent path refuse,
by design. That refusal is correct behaviour, not a bug. `BVP_HUMAN_APPROVAL=true` re-arms
the old gating on all five.

**3. Commit messages: use a FILE, not `-m "…"`, for anything containing backticks.** Bash
runs them as command substitution inside a double-quoted argument. It silently produced no
commit and a push reporting everything-up-to-date.

`lib/bvp.sh` or `safe-commands.sh` and a suite starts failing on a "pre-change" case, the
ground-truth lookup is what broke, not the fix. `safe-commands` uses a behavioural search
(immune); the two bvp suites use `git log -S` and depend on their anchor NOT being quoted in
any comment — which is stated in each, and is exactly the trap that already defeated six
detectors here.

file that fixes it makes every naive detector match the fix.* A remediation comment quoting
