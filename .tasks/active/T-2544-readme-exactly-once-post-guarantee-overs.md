# T-2544: README Exactly-once-post guarantee overstated — omits G-088 hub-restart caveat (in-memory dedupe, reliability doc-accuracy)

## Context

Second finding of the campaign's Reliability lens (sibling of T-2543). README
§Exactly-once-post claims absolutely: "client retries are absorbed by hub-side
`(sender, client_msg_id)` dedupe; the CLI's offline queue persists unsent posts
across hub blips and replays them safely." This overstates the guarantee across a
HUB RESTART: the dedupe recogniser is IN-MEMORY only
(`crates/termlink-hub/src/dedupe.rs` — a `Mutex<map>` built fresh with ttl_ms +
capacity, no disk persistence), while the CLI offline queue replays the
idempotency key DURABLY. So after a hub restart the dedupe map is empty and a
replayed retry double-applies. This is already a registered gap — **G-088**
("post-idempotency exactly-once does not survive a hub restart — the dedupe
recogniser is in-memory while the client replays the idempotency key durably").
Fix = README caveat naming the restart boundary (no code change; the fix for the
underlying behavior is G-088's own remediation, human-gated). Same doc-accuracy
class as T-2543.
