## Context

`fw doctor`'s `secret_cache` check (`infrastructure.rs:492`) resolves its scan
directory via `std::env::var("HOME").unwrap_or_default()` — when HOME is unset the
empty string yields a CWD-relative `.termlink/secrets` that almost never exists, so
the check reports a false-clean `pass: "no cached secrets"` on the auth-drift
signal. Sibling CLI outlier to T-2629 (same T-2607 HOME-unset class). Found by the
T-2628 round-3 portability hunt.

## Acceptance Criteria

### Agent
- [ ] The doctor secret_cache check resolves its directory via the canonical `config::termlink_config_dir()` (hardened in T-2629), NOT via ad-hoc `HOME.unwrap_or_default()` — so HOME-unset no longer produces a CWD-relative false-clean
- [ ] Behavior is preserved when HOME is set: the scanned dir is still `$HOME/.termlink/secrets`
- [ ] A `secret_cache_dir()` helper is extracted with a unit test asserting the cache dir is derived from (lives under) `termlink_config_dir()`
- [ ] `cargo test -p termlink --bins` passes; fix committed and finalized through P-011; pushed to OneDev

## RCA

**Symptom:** With HOME unset, `fw doctor`'s secret_cache check reports a green
`pass: "no cached secrets"` even when real `~/.termlink/secrets/<host>.hex` caches
exist — a false-clean on the auth-drift (secret-rotation) early-warning signal.

**Root cause:** `infrastructure.rs:492` resolves the scan dir with
`HOME.unwrap_or_default()`; the empty-string default yields a CWD-relative
`.termlink/secrets` that almost never exists, short-circuiting to the "pass" arm.
A sibling of T-2629's config.rs outlier — both bypass the canonical resolver with
their own ad-hoc HOME reads.

**Why structurally allowed:** T-2607 unified HOME-unset resolution for the trust
plane in one crate; the CLI crate accreted multiple independent `HOME.unwrap_or(...)`
sites, and this doctor block only misbehaves when HOME is unset (an uncommon dev
condition), so it stayed dark.

**Prevention:** Route the check through the single hardened resolver
`config::termlink_config_dir()` (T-2629) via an extracted `secret_cache_dir()`
helper with a unit test locking the derivation. The HOME-unset resolution
semantics are load-bearing-proven in T-2629's config_dir tests.
